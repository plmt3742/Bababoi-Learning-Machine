# ADR-002: MVP 范围与 P0/P1/P2

- 状态：Proposed（已确认：大学理科、多模态识图、数据库由人机负责；登录/SSE 待确认）
- 日期：2026-11-04
- 决策人：霹雳马桶、人机
- 相关任务：DS-001、SH-001、SH-006
- 相关文档：`docs/agent/01-project.md`、`docs/agent/02-goals.md`、`docs/agent/09-risks.md`

## 1. 背景

docx 描述的是一个长期大创项目：图像识别、知识图谱、模型训练、个性化推荐、动态学习。实验室考核只有 25 天、2 人，且 11.29 要现场演示。必须明确“这次做什么、不做什么”，否则范围会失控。

## 2. 决策

本次 MVP 以**核心闭环 + 可演示稳定性**为唯一目标：

```text
文本录入错题 → AI 分析 → 生成 3 道相似题 → 保存 → 练习 → 统计
```

### P0（11.21 前必须完成）

1. 最小登录（注册/登录/JWT/退出）
2. 文本录入错题（题干/答案/学科/标签）
3. 图片录入（P0 增强）：电脑上传；手机拍照/相册；DeepSeek `deepseek-flash` 识图；结果可编辑；文本兜底
4. AI 分析（知识点/题型/难度/错误原因）
5. 生成 3 道相似题（题干/答案/解析/校验）
6. 错题列表/详情/编辑/软删除
7. 学科/标签筛选 + 关键词搜索
8. 练习模式（作答/计时/自评/记录）
9. 学习概览（错题数/练习数/正确率/薄弱知识点）
10. 部署 + 种子数据 + 演示兜底

### P1（有余力再做）

- 重新生成/质量反馈
- 错题导出
- 复习提醒/简单间隔重复
- 移动端其余页面适配（录入入口已在 P0）
- token 级流式（P0 只做阶段级 SSE）
- 多图/批量上传

### P2（本次不做）

- 知识图谱可视化
- 模型训练/微调/强化学习
- 复杂个性化推荐
- 社区/教师端/付费/多租户
- 全学科深度覆盖

### 非目标

- 不做拍照解题/答案搜索
- 不做完整后台管理
- 不做复杂社交
- 不做需要标注数据/训练的功能

## 3. 后果

### 正面

- 25 天可以交付一个完整闭环，演示路径清晰。
- 前后端工作量可控，联调风险低。
- 答辩可以讲“完成度 + 稳定性 + 质量校验”，而不是“功能很多但都不深”。

### 负面/代价

- 与 docx 的宏大愿景有差距，需要在 PPT 中解释“长期规划 vs 本次 MVP”。
- 知识图谱/模型训练等亮点缺失，需要用“闭环 + 质量校验 + 工程化”补足；图片识图已覆盖。
- 图片识图是 P0 增强：如果延期，演示退回文本，但接口/设计保留；不要让识图拖垮文本闭环。

### 风险与缓解

| 风险 | 缓解 |
|---|---|
| 范围蔓延 | 新增 P0 必须删一个 P0；11.21 后冻结功能 |
| 图片识图拖慢主闭环 | 文本入口必保；识图 11.21 前可用即可；延期则演示用文本 |
| 评审觉得功能少 | PPT 强调闭环深度、质量校验、工程流程、数据指标 |
| 两人对 P0 理解不一致 | 11.7 前逐项确认本 ADR，改为 Accepted |

## 4. 备选方案

| 方案 | 优点 | 缺点 | 为什么没选 |
|---|---|---|---|
| 按 docx 全做 | 覆盖全 | 25 天不可能；每项都浅 | 交付风险极高 |
| 只做“生成 3 题” | 最聚焦 | 缺少练习/统计，闭环不完整；演示单薄 | 产品价值不足 |
| 先做独立 OCR 再做闭环 | 演示炫 | 独立 OCR 对公式/图表不稳定；主闭环没跑通 | 本末倒置 |
| 做知识图谱 | 技术亮点 | 成本高、演示收益低、无数据 | 不划算 |

## 5. 实施要点

- 11.7 前把本 ADR 改为 Accepted；两人逐项确认 P0。
- 11.14 的退出条件是“核心闭环 + 部署”，不是“功能多”。
- 11.21 后冻结新功能；只修 bug/体验。
- 任何 P0 变更写进 `04-todos.md` 并在站会说明。
- 答辩时明确区分“本次 MVP”与“未来规划”。

## 6. 复审条件

- 11.10 核心闭环仍未跑通 → 进一步砍 P0（比如先不做搜索/标签）。
- 11.14 已提前完成闭环且有 3 天余力 → 可把识图交互做完整；不再加独立 OCR。
- 产品评审明确要求某项 → 用“删一个同等工作量 P0”交换。
