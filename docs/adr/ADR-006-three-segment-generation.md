# ADR-006: 生成链路改为「三段并发，每段 1 道」

- 状态：Accepted
- 日期：2026-11-06
- 决策人：霹雳马桶、人机
- 相关任务：BE-007、BE-015、BE-021、FE-009、FE-023
- 相关文档：`docs/agent/05-architecture.md`（§6.4/§7.2/§7.3/§8）、`docs/agent/14-generation-three-segments-reply.md`、`docs/agent/15-backend-sync-20261106.md`、`docs/product/01-prd-lite.md`（FR-5）、`docs/agent/16-three-segments-frontend-review.md`（已归档；三段并发结论 + 后端处置记录）
- 前序讨论：人机《待确认单 · 生成链路改三段并发》（2026-11-05，含实测数据），前端《生成接口变更单》《生成提示词单》

## 1. 背景

BE-007 的初版是**一次 LLM 调用出 3 道题**（`{"questions": [...]}`，校验器要求恰好 3 题）。跑真模型后暴露三类问题：

1. **三题雷同**。0.7 温度下 batch 的三题两两相似度实测 0.907–0.950 —— 基本是同一个模板换个函数式，"举一反三"变成了"抄三遍"。
2. **题型经常跑偏**。6 轮 batch 里只有 3 轮三题题型全符合预期；一道题里同时约束 3 段的题型、难度、格式，模型会自己取舍。
3. **重试代价是整组**。一次坏输出（JSON 截断、空位数不匹配、与原题雷同）就让 3 道全部重出，含参题重出一轮 25–36s，最坏 58s×2 ≈ 116s，贴着 120s 硬超时。

前端在《生成接口变更单》里提议改成三段并发（每段 1 道），我做了 A/B 实测再拍板。

## 2. 决策

**一次生题 = 排 3 个任务（`target_index` = 1/2/3），每个任务只生成 1 道题。**

| 项 | 口径 |
|---|---|
| 难度档 | 默认 `easy / medium / hard` 递增（相对原题：少一步 / 相当 / 多一步或加干扰条件）；接口收 `difficulties`，自定义 UI 留 P1 |
| 接口 | `POST /questions/{id}/generate` 返回 `{"tasks":[{"task_id","target_index","difficulty"}]}`；**不再返回单个 `task_id`**（11-08 冻结前一次切净） |
| 单段 | `target_index` 有值时只排那一段，收单个 `difficulty` |
| 替换 | 整组重生成：**入队即软删旧组**，前端出 3 张骨架卡，每段成功只写自己那一格；单段重生成只换自己那格 |
| 失败隔离 | 一段失败不影响其余两段；该段可单独 retry（自动 requeue 1 次，手动 retry 不限次） |
| 题型 | **软约束**：首选与原题一致，允许换题型，照常入库，**不新增 `TYPE_MISMATCH`** |
| 校验 | 每段 1 题；**与原题、与同组其它格都只拒「归一化后逐字相同」**，不套 0.9（14 号 D3 原写「与原题 <0.9 保留」，拆段后实测把它改掉了，见 §3.1）。归一化覆盖空白/全半角标点/`$`与`\\(\\)`/`\\left`-`\\right` 等排版宏，**不覆盖** `\\ln` 与 `\\log_e` 这类语义等价写法（§4 的遗留项） |
| 并发 | `TASK_MAX_CONCURRENCY` 默认 6（原 2） |
| 重试窗口 | requeue 前判 `now - started_at > 90s` 则不再排，直接 failed |
| prompt 版本 | `generate_v1` → `generate_v2`（输出形状变了，必须计版） |
| 采样 | quiz `temperature=0.3`、`max_tokens=6000`（单题实测到过 3589 token，4000 只剩 10% 余量；上限不计费） |
| 取消 | P0 不做真取消，不加 `/tasks/{id}/cancel`；前端只保留「暂停自动刷新」 |

## 3. 实测依据（同一道含参题，各 3 轮，`deepseek-flash`）

| 指标 | batch 一次 3 道 | 3 段并发各 1 道 |
|---|---|---|
| 整组墙钟 | 中位 24.7s / 最坏 35.6s | 中位 22.1s / 最坏 24.5s |
| 单段延迟 | — | 3.5–26.0s |
| 每轮 token（入+出） | 7,002 | 9,656（**成本 1.38×**） |
| 三题里最像的一对 | 0.950 / 0.911 / 0.907 | 0.741 / 0.900 / 0.643 |
| 题型符合 | 6 轮里 3 轮全符合 | **27/27 轮全符合**，难度档 27/27 被采纳 |
| 429 | 0 | 0（约 30 次调用，含 3 段同瞬间并发） |
| 坏输出重试代价 | 重出整组 25–36s（最坏 ≈116s） | 只重出该段 3.5–26s |

三条真实收益是**题型符合率、三题去雷同、重试只花一段**；代价是 **成本 1.38×**，且**整组墙钟并不会变快**（并发取的是最长那一段）。这两点在 PRD/05 的措辞里都按实测改掉了，没有写成"快 3 倍"。

### 3.1 拆段之后被新数据改掉的一条：与原题的 0.9 相似度阈值

`05 §7.2 第 3 条` 原来写「与原题归一化相似度 <0.9 保留」，那是 batch 时代测出来的数（当时与原题 ≤0.833，因为一次要出 3 道，模型自己会拉开差异）。落地三段后同一道含参题重测 2 轮 ×3 段（`backend/scripts/measure_segment_similarity.py` 可复现）：

| 轮次 | ≥0.9 被判死的段数 | 被判死的输出实际是什么 |
|---|---|---|
| 第 1 轮 | 4/9 | `$x^2-a\ln x$`、`$x-a\ln(x+1)$`、`$x-a\ln(x+2)$` 等 |
| 第 2 轮（同时把提示词第 7 条加严成"必须换函数族/换问法"） | 3/9 | `$x-ae^x$`、`$ax-\ln x$`、`$ax^2-\ln x$` 等 |
| 两轮合计逐字抄原题 | **0/18** | —— |

两个结论：

1. **0.9 这条从来没拦到过抄题，只拦到过模板。**含参/固定句式题型的合法新题相似度就落在 0.90–0.97，与"真抄"的分布重叠，任何 0.9–0.97 的阈值都分不开——数值相似度在这个场景没有鉴别力。
2. **提示词加严不是解药。**第 2 轮把"数值和情境必须不同"扩写成"要换函数族/换条件/换问法"，判死率只从 4/9 变成 3/9（输出质量确实更发散，但相似度没降下来）。所以这条装饰性措辞最后撤回了，改的是判据本身。

据此与原题的判据统一成「归一化后逐字相同」，与同组其它格一致。**这是对 14 号 D3 的一处偏离**，随 PR 标注并发前端确认；如果产品坚持要禁"同模板换数字"，需要的是一条比公式结构差异的判据，不是调相似度阈值（记在 §7 复审条件）。

## 4. 后果

**正面**

- 单段可重试、可独立显示状态，详情页三张卡的状态机与用户预期一致。
- 每段提示词只描述一个目标，题型/难度/格式的遵循率显著上升。
- 落库带 `target_index`，"哪一格出的题"变成可查的事实，统计能按段算成功率。

**负面 / 需要注意**

- **成本 1.38×**：同样一道错题的巩固成本上升三分之一，`ai_call_logs` 要按段记 token，估算吞吐时不能再用旧的单次成本。
- **任务中心一次生题出 3 行**：列表必须折叠成「生题 2/3」，否则连续录 10 题会有 30 行。
- **三段并发写同一组时的查重有竞态**：校验只比"其它格已落库的题干"，两段同时在跑时互相看不到，仍可能出逐字相同的题。MVP 接受（14 号 §2.1-3），不上锁、不引入唯一索引。
- **同组两格可能出同一个函数式**：端到端实录里出现过第 1 格 `设函数 $f(x)=2x-a\ln x$…讨论单调性` 与
  第 3 格同一函数式只多挂一个小问 —— 归一化后不完全相同，所以入库了。这是把"换汤不换药"从
  判死换成放行的直接代价（反过来，同一次跑里第 2 格吐了与第 1 格**逐字相同**的题干，被这条判据拦下、
  该段置 `queued` 等重排，说明判据仍有牙；但脚本每段只跑一遍，"重排后确实出得来新题"这半句**还没实测**，
  不写成已验）。要真解决得比公式结构，记 P1 **BE-022 同组公式结构去重**，且只做 warnings 提示不判死
  （16 号 §三：误判的代价是用户看到"三题里有一题不能用"）。
- **入队即软删旧组**：整组重生成期间用户看不到旧题，产品已确认接受；但这也意味着**误点一次生成就把旧组推入历史**，靠软删留痕兜底。
- 三段各自占用并发位，`TASK_MAX_CONCURRENCY=2` 会让第 3 段干等一整轮，所以默认提到 6。

## 5. 备选方案

| 方案 | 为什么不选 |
|---|---|
| 维持 batch，加"三题彼此相似度 <0.9" | 实测 0.907–0.950 说明 batch 自己就过不了这条；拦下来的结果是整组重出，代价最大 |
| batch + 题型硬约束（不符即失败） | 6 轮里 3 轮会因题型跑偏判死，失败率高于收益；且换题型本身不是错（14 号 D7） |
| 一次调用出 3 道、拆成 3 条 `generated_questions` 分别入库 | 保留了 batch 的雷同与重试代价，只拿到"按格显示"的外观，属于半成品 |
| 三段串行（一段一段等） | 墙钟变成 3 段之和（约 40–60s），比 batch 更慢，没有任何额外收益 |
| 用 `n=3` 一次采样 3 份 | DeepSeek 兼容接口的 `n` 不保证返回多份独立结果，且拿不到分段难度；没实测通过就不写进链路 |

## 6. 接口与数据影响（摘要）

- `questions.generated_questions` 加列 `target_index INT NULL`；`generation_task` 加列 `difficulty VARCHAR(16) NULL`。迁移 `3f9c1a7e5b24` 两条都加，downgrade 可逆。
- 新增索引 `ix_generated_parent_slot (parent_question_id, target_index)`，详情页与按格替换按它取数。
- 同一笔迁移**给历史活跃行回填 `target_index`=1/2/3**（按 `parent_question_id, created_at, id`，就是旧版一次 3 道的插入顺序；软删行与超出 3 条的留 NULL）。用逐行 UPDATE 而不是相关子查询：MySQL 8 禁止 UPDATE 的表同时出现在子查询里（error 1093）。upgrade、downgrade、以及 downgrade 后老数据仍读得到，都实测跑过。
- `POST /questions/{id}/generate` 响应形状变更（破坏性，前端 FE-023 #28 已做双向兼容）；**后端只发 `tasks`，从未双发顶层 `task_id`**，FE-023 那条兜底分支可以直接删（16 号 §五）。`GET /tasks` 的 `TaskOut` 多 `difficulty`，`GeneratedQuestionOut` 多 `target_index`。
- 错误码零新增：段失败仍用 `AI_TIMEOUT` / `AI_PROVIDER_ERROR` / `AI_INVALID_OUTPUT` / `INTERNAL_ERROR`。

## 7. 复审条件

- 生产 RPM/TPM 触顶或 429 不再是 0 → 回调 `TASK_MAX_CONCURRENCY`，或给生题单独排队列。
- 单段成本口径变了（模型换档、涨价、按次计费）→ 重新算 1.38× 这个数，必要时评估"两段（medium + hard）"折中。
- 三格重复题的实际投诉出现 → 再考虑把查重从"落库时比"升级为"入队前占位"。
- 产品如果坚持禁止「同模板换数字/换函数式」→ 不能回来调相似度阈值（§3.1 已证明它分不开），要新增一条比公式结构/参数集合的差异判据，并重新定义"什么算新题"。
- P1 放开用户自定义难度后，`SEGMENT_DIFFICULTIES` 从写死变为入参 → 本 ADR 的难度档一节需升版。
