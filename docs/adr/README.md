# ADR 索引

ADR = Architecture Decision Record（架构决策记录）。用来记录**不可逆或跨模块**的决定，避免“为什么当时这么定”只留在聊天记录里。

## 什么时候写 ADR

- 技术栈/框架/数据库/部署方式的选型或变更。
- API 风格、认证方式、数据模型的关键取舍。
- 范围裁剪（比如“不做独立 OCR，改用多模态识图”）。
- 引入新的基础设施（Redis、队列、对象存储等）。
- 任何“以后再改成本很高”的决定。

不需要写 ADR：变量命名、样式微调、单个 bug 修复、日常任务拆分。

## 状态

| 状态 | 含义 |
|---|---|
| `Proposed` | 已提出，待两人确认 |
| `Accepted` | 已确认，按此执行 |
| `Superseded` | 被新 ADR 取代（注明新 ADR 编号） |
| `Deprecated` | 不再使用，但保留记录 |
| `Rejected` | 评估后不采用（保留原因） |

## 命名

`ADR-<三位编号>-<短横线标题>.md`，例如 `ADR-001-tech-stack.md`。

## 写 ADR 的最小结构

1. 背景：为什么现在要决定？
2. 决策：我们选了什么？
3. 后果：得到什么、放弃什么、有什么风险？
4. 备选：还考虑过什么，为什么不选？
5. 链接：相关文档/Issue/PR。
