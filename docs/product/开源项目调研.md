## 2. A 档：同域完整实现

### 2.1 wttwins/wrong-notebook — 智能 AI 错题本

| 项 | 值 |
|---|---|
| 链接 | https://github.com/wttwins/wrong-notebook |
| Stars / 活跃度 | 811 ★，2026-08 仍在提交，MIT |
| 技术栈 | Next.js 16 + React 19 + Prisma/SQLite + NextAuth（与团队栈不同，看产品与流程） |

功能覆盖是所有候选里最全的，几乎就是 PRD 功能清单的成品版：

- AI 识别题目 → 自动生成解析、知识点标签、同类练习题（对应 FR-2/4/5）
- 多错题本管理、智能标签、按掌握状态/时间/标签/年级多维筛选（FR-6）
- 基于错题生成相似练习题（FR-5）、数据统计可视化（FR-10 参考形态）
- 多用户注册登录、数据隔离、管理员后台（FR-7）
- 一键导出筛选后的错题，可自定义打印内容，支持 PDF
- AI 配置动态切换：Gemini / OpenAI / Azure，网页设置即时生效；OpenAI 兼容模式可直接接硅基流动、智谱 GLM、Kimi、DashScope

**借鉴点**：产品功能全景对照；「AI 提供商网页配置 + 兼容模式」的设计（模型选型待定时的解耦方案）；错题本筛选维度设计。

### 2.2 TianFusheng136/cuoti-ai — AI 错题复盘工作台

| 项 | 值 |
|---|---|
| 链接 | https://github.com/TianFusheng136/cuoti-ai |
| Stars / 活跃度 | 3 ★，2026-10-18 更新，闭环已完成并验收 |
| 技术栈 | React + Vite + FastAPI + SQLite + KaTeX，OpenAI 兼容 / Gemini 双接口 |

**工作流与本项目 PRD 逐条对应，工程细节最值得抄**：

- 图片上传：JPG/PNG/WebP、扩展名 + 文件签名 + 尺寸 + 15 MB 校验（FR-1，比 PRD 的 10 MB 更严）
- 识别：视觉模型识别，结果用 Pydantic/JSON Schema 严格校验，保存模型名、耗时和 `recognition-v1` 提示词版本（FR-2）
- **人工确认：图片与识别文字双栏确认页，用户明确确认前题目保持未确认状态，确认文本哈希与识别快照分开保存**（FR-3 的完整工程实现，正是 PRD「识别结果暂存不入库」的落地方式）
- 整理：`analysis-v1` 提示词 + `analysis-schema-v1` 输出 Schema；候选错因列表 + 学生自主选择补充真实错因（FR-4）
- 生题：同知识点 / 换场景 / 提高难度三类变式题，分别生成、分别验算，失败只重试失败类型（FR-5，比 PRD 的固定 3 道更细）
- Markdown + 本地 KaTeX 公式渲染（FR-9）、搜索/学科/知识点/掌握状态筛选的错题本（FR-6）、间隔复习（FR-8）

**借鉴点**：识别-确认-入库的状态机设计；提示词与输出 Schema 版本化管理；变式题分类生成与失败定向重试。

### 2.3 Annex-cfzy/Recall-wrong-questions — Recall AI 智能错题本

| 项 | 值 |
|---|---|
| 链接 | https://github.com/Annex-cfzy/Recall-wrong-questions |
| Stars / 活跃度 | 0 ★（很新），2026-08-31 |
| 技术栈 | **Vue 3 + Vite + TypeScript + FastAPI + SQLAlchemy + SQLite(FTS5) + DeepSeek + PaddleOCR-VL，与团队选型完全同款** |

核心链路「录入 → AI 识别归档 → SM-2 复习 → 数据分析」，目录分层清晰（api 路由 / services 业务 / models ORM / schemas Pydantic），services 层按 `ocr / ai / sm2 / vector / export / insight` 划分。

两个值得注意的设计：

- **AI/OCR 服务缺失时自动降级为本地 Mock**，零云依赖也能跑通全链路——演示兜底的好办法
- OCR 用 PaddleOCR-VL、文本模型用 DeepSeek——正好规避了「DeepSeek 没有多模态 API」的问题，佐证 PRD「识别走多模态模型」的决策

**借鉴点**：同技术栈的代码骨架与分层方式可直接参考；注意其 Stars 极少、未经大规模验证，当结构参考而非代码搬运。

## 3. B 档：单点深挖

### 3.1 Albertdeng23/GEEQuestionBank — 考研智能题库（相似题两条路线）

| 项 | 值 |
|---|---|
| 链接 | https://github.com/Albertdeng23/GEEQuestionBank |
| Stars / 活跃度 | 12 ★，2025-10 |
| 技术栈 | Flask + VLM + Sentence-Transformers（BGE 中文向量） + MathJax |

对 FR-5「相似题」给出了两条可对照的技术路线：

1. **检索式**：题目向量化入库，上传图片识别后按语义相似度返回最相似的 3 道（带来源与相似度分数）——好处是题目真实可控，坏处是需先建题库
2. **生成式**：VLM 分析考点后动态生成 3 道考点类似、内容全新的题，LaTeX 渲染——PRD 目前选的是这条

MVP 建议维持生成式；若演示时被问「生成的题质量怎么保证」，检索式可作为加分回答方向。

### 3.3 tjunsh/ai-wrong-notebook — AI 错题本（Android/Flutter）

| 项 | 值 |
|---|---|
| 链接 | https://github.com/tjunsh/ai-wrong-notebook |
| Stars / 活跃度 | 117 ★，2026-10-18 更新，有 CI/Release |
| 技术栈 | Flutter + Riverpod + Drift(SQLite)，OpenAI 兼容多模态模型 |

PRD 不做移动端，但它的**请求调度设计**直接对应 PRD 的失败处理条款：

- 连续扫题排队解析，避免并发重复消耗（对应「超时重试 1 次」）
- 一图多题逐题解析、失败题单独重试、已成功题不受影响（对应「失败重拍、重试上限 2 次」）
- 解析后可选择「保存到错题本」或「放弃」——识别结果不入库的另一处佐证

AI 视觉分析输出科目、题干、答案、关键步骤、错因、知识点，字段划分可作为 FR-2/FR-4 输出结构参考。
