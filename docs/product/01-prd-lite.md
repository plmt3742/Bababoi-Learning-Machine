# 01 · PRD-lite

> 目标：一页纸讲清“给谁、解决什么、怎么用、先做什么”。45 分钟内填完，不要写成大创申报书。
> 本文是**速览**，不是完整契约；详细范围/交互/验收以 `docs/product/PRD.md`（当前在 `docs/prd` 分支，v0.8，待修订为 v0.9）为准。

## 1. 一句话

把一道错题变成三道同类题，并追踪掌握度的 AI 错题巩固平台。

## 2. 目标用户与场景

| 项 | 内容 |
|---|---|
| 主用户 | 大学理科生（高数/线代/概率论/大学物理为主） |
| 具体画像 | 大二理工科学生，高数/线代/概率论/大学物理有稳定错题来源；习惯拍照或截图保存；愿意每周花 10–20 分钟整理；电脑端上传图片，手机端拍照/相册 |
| 扩展方向 | 高中/其他学科作为后续扩展，优先级低；P0 不增加学段配置，数据模型保留 `subject` 字符串 |
| 使用场景 | 课后作业批改后、期中/期末复习前、错题集中整理时 |
| 现有替代 | 手抄错题本、拍照搜题 App、题库 App、Excel/笔记软件 |
| 现有不足 | 整理耗时难坚持；看懂原题但缺少同类练习；不知道哪个知识点反复错，复习没重点 |

## 3. 用户问题（最多 3 个）

1. 错题整理耗时，难以坚持。
2. 看懂了原题，换个情境又不会。
3. 不知道哪个知识点反复错，复习没重点。

## 4. 核心闭环

```text
录入（文本/图片）→ 识别/分析 → 显示题目内容 → 编辑
→ 保存 → 后台整理/生成 → 练习 → 记录/统计/错题本
```

每一步的用户动作、系统反馈、失败兜底：

| 步骤 | 用户动作 | 系统反馈 | 失败怎么办 |
|---|---|---|---|
| 录入（文本） | 粘贴/拖入题干、答案，选题型/学科 | 校验、进入编辑器 | 提示错误；保留输入 |
| 录入（图片） | 电脑粘贴/拖入；手机相册/拍照 | AI 预框核心题目 → 用户确认 → 裁剪识图 | 重拍/换图/改文本；不丢输入 |
| 识别/分析 | 确认识图结果 | 结构化题目 + 知识点/题型/错误原因 | 重试；不丢输入 |
| 显示/编辑 | 在编辑器改题干、选项、空位、答案 | 按题型模板显示；工具栏辅助 | KaTeX 错误标红；内容不丢 |
| 保存 | 点【保存】 | 入库；草稿清理 | 失败保留本地草稿；可重试 |
| 后台整理/生成 | 保存后自动入队 | 任务中心显示排队/生成/完成/失败 | 失败重试；不阻塞连续录入 |
| 练习 | 作答、提交、自评 | 对错 + 解析 + 记录 | 提交失败可重试 |
| 记录/统计/错题本 | 查看错题本、任务中心、统计 | 错题管理 P0；统计/概览 P1 | 空状态引导 |

> 练习为 **P0**；学习统计/概览为 **P1**；复习模式为 **P1**（11.7 前不做）。

### 4.1 图片录入的“框题确认”流程（P0 增强）

```text
拍照/上传 → AI 检测题目区域 → 框定最可能的核心题目
→ 用户确认“是这道题吗？”/切换候选/移动缩放 AI 框
→ 裁剪/识图 → 可编辑题干 → 分析
```

- 目的：一张图可能有多道题或无关内容，先框定再识别，降低识图错误。
- 决策：P0 框定 1 道最可能的题，用户可确认/切换候选，并可**移动/缩放 AI 框**；从零画框 P1。
- 整页/无候选：AI 判定整页 → 整页识别不框；无 candidate 或 grounding 不可用 → 整图识别。
- 降级：仍失败则退回文本录入。

## 5. 范围

### P0（演示必须）

- [ ] 最小登录
- [ ] 文本录入：电脑粘贴/拖入；手机输入兜底
- [ ] 图片录入：电脑粘贴/拖入；手机相册/拍照；AI 预框 + 用户确认/切换 + 移动/缩放 AI 框
- [ ] 三种题型 + 工具栏（P0 增强）：选择题、填空题、解答题；LaTeX/编号/表格/插图按时间降级
- [ ] AI 分析（知识点/题型/错误原因）
- [ ] 生成 3 道相似题（题干/答案/解析）
- [ ] 错题列表/详情/编辑/删除
- [ ] 学科/标签筛选 + 搜索
- [ ] 练习 + 记录（P0）
- [ ] 任务中心：列表 + 状态 + 失败重试 + 草稿行
- [ ] 草稿：服务端 + localStorage 双写
- [ ] 部署 + 种子数据

### P1（有余力）

- [ ] 学习统计/概览：4 个数字 + 薄弱知识点 + 趋势图
- [ ] 复习模式
- [ ] 单题重新生成/质量反馈（P0 基础版可先做）
- [ ] 导出
- [ ] 移动端其余页面适配
- [ ] token 级流式
- [ ] 多图/批量上传
- [ ] 从零画框/手动绘制

### P2（不做）

- [ ] 知识图谱
- [ ] 模型训练
- [ ] 复杂推荐
- [ ] 社区/教师端/付费
- [ ] 独立 OCR / 开源 OCR 兜底

### 非目标

- 不做拍照解题/答案搜索
- 不做完整后台
- 不做需要标注数据/训练的功能
- 不使用独立 OCR；只走 DeepSeek 多模态识图

## 6. 成功指标（最多 3 个）

| 指标 | 目标 | 怎么测 |
|---|---|---|
| 核心闭环完成时间 | < 3 分钟 | 可用性测试 |
| 生成题可作答率 | ≥ 80% | 人工抽检 20 组 |
| 识图/框题可用率（大学理科含图/公式） | ≥ 80% | 人工抽检 10 张（框题 top-1 + 识图文本） |

## 7. 关键假设

1. 用户愿意粘贴文本，或上传/拍摄图片；识图结果允许修正。
2. DeepSeek API 在演示期间稳定，文本+图片成本可控。
3. 评审更看重闭环完成度与稳定性，而不是功能数量。

## 8. 最大风险（最多 3 个）

1. 范围过大，25 天做不完 → 砍 P1/P2，11.21 后冻结新功能。
2. AI 输出不稳定/答案错误 → 结构化校验 + 重试 + 人工抽检 + 用户反馈。
3. 部署/演示翻车 → 11.14 staging + 预生成缓存 + 录屏兜底。

## 10. 一句话验收

一个没听过项目的人，看完演示能说出：**“它把错题变成同类题，并告诉我哪个知识点没掌握。”**
