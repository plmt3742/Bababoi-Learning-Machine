## 二、相似度判据：我同意改，但建议补归一化

**你的数据我认。** 判死 4/9、3/9，被判死的是 `x^2-a\ln x`、`ax-2\sqrt x`、`x+a/x` 这类换了函数族的正常新题；18 段里逐字抄题 0 段；合法输出最高 0.967 与"真抄"分布重叠——**0.9 这个阈值确实没有鉴别力**。把判据从"相似度阈值"改成"逐字相同"方向是对的。

**我的意见（一条建议，不是要求）**：把「逐字相同」明确成「**归一化后**逐字相同」。

归一化至少要覆盖：

| 归一化 | 举例 |
|---|---|
| 去所有空白 | `$x^2 $` ≡ `$x^2$` |
| 全角/半角统一 | `（` ≡ `(`，`，` ≡ `,` |
| 定界符统一 | `$...$` 与 `\(...\)` 视为同一 |
| 常见等价写法 | `\left(` / `\right)` 与 `(` / `)` |

**理由**：不做归一化，"抄题"只要多敲一个空格就漏过去了。而这条规则的**唯一价值**就是拦住真抄——漏判等于这条规则白写。

**如果你倾向不归一化**，也说得通（实现最简），但建议在 `05` 里写清"这是弱判据，只拦逐字节完全一致"，避免以后被当成"已保证不抄"。

## 三、同组两格出同一个函数式：建议放 P1

**现象成立**：第 1 格 `2x-a\ln x` 讨论单调性、第 3 格同一函数式多挂一个小问——这确实是"换汤不换药"。

**但我建议 P0 不做结构判据**，理由三条：

1. 要比较 `$...$` 里的数学式结构，得先做表达式解析/规范化（`2x-a\ln x` 与 `2x - a \ln x` 与 `2x-a\log_e x` 算不算同一个？），成本不小。
2. 误判代价高：判"重复"后要么替换、要么标红，两条路都会让用户看到"三题里有一题不能用"。
3. P0 已经有 `too_easy` / `too_hard` 的用户反馈通道，可以先靠人工兜。

**建议**：记进 P1，名称写"同组公式结构去重"；P0 只在 `warnings` 里给一个"与第 n 题函数式相近"的**提示**，不判死。

## 五、双字段：建议删掉 `task_id`

**背景**：之前定的口径是"不留双字段、一次改干净"（这条最初也是你自己提的）。现在报告里提到"兼容旧 task_id"，需要明确是哪种：

| 情况 | 建议 |
|---|---|
| 前端 FE-023 只读 `tasks` | **直接删 `task_id`**，响应里只保留 `tasks` |
| 后端同时返回 `task_id` 和 `tasks` | **删 `task_id`** |

**理由**：

1. **两个事实源**。`task_id` 指哪一段？第一段？整组？没人说得清，前端各写各的。
2. **永久债**。等所有调用方都迁到 `tasks` 后，也没人敢删 `task_id`——因为不确定还有谁在用。
3. **测试双倍**。两种形状都要覆盖，而且"旧形状"永远测不到真实路径。
4. **前端已经没有依赖**。FE-023 已合，读的是 `tasks`。

**核对方式**（一条命令）：

```bash
grep -rn "task_id" frontend/src | grep -v "tasks\[" | head
```

如果只在 `tasks[]` 内部用到 `task_id`，说明没有顶层依赖，可以放心删。

## 七、前端配套（我这边负责，不用你管）

- 三张卡**不假设同题型**，每张卡自带题型徽章；混排时按实际类型渲染
