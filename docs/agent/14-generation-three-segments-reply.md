## 2. 05 / 数据模型 / 接口

| # | 决定 |
|---|---|
| D1 | `POST /questions/{id}/generate` 请求收 `difficulties`（整组）或 `difficulty`（单段）；返回 `{"tasks":[{task_id,target_index,difficulty}]}`；**不再返回单个 `task_id`** |
| D2 | generate prompt：同知识点、同难度、**题型首选与原题一致（软约束，允许换题型）**；难度按指定档（相对原题：少一步/相当/多一步） |
| D3 | 每段 1 题；与原题相似度 <0.9 保留；三题彼此**只拒归一化后完全相同**，不套 0.9（实测会误杀） |
| D4 | `target_index` 整组也记 1/2/3；active 去重键 = `question_id + stage + target_index` |
| D5 | **`generated_questions` 加 `target_index`**（缺列会导致①②③错位，必须加） |
| D6 | `generation_task` 加 `difficulty`（nullable，downgrade 可逆） |
| D7 | **不新增 `TYPE_MISMATCH`**；题型是软约束，换题型照常入库；段失败沿用 `AI_*` / `INTERNAL_ERROR` |
| D8 | 重试用任务级 requeue：`now - started_at > 90s` 不再排；不是同调用内重试 |

### 2.1 三个洞的决定

1. `generated_questions.target_index`：**加列**。
2. 整组替换：**按格替换**；入队时软删旧组 + 骨架卡，每段成功写自己的 `target_index`。
3. 三题彼此重复：**落库时与同组已存在题比一次，只拒完全相同**；并发竞态 MVP 接受，不把 0.9 加回来。

## 3. analysis 的 `answer_md` / `explanation_md`（这是 #5/#6 的阻塞）

**决定：走 `questions.answer_md` / `questions.explanation_md` 正字段，不塞进 analysis JSON。**

- `AnalysisResult` 增加 `answer_md`、`explanation_md`（非空）；
- `analysis_messages` 的 JSON 字段说明加这两项；
- `_apply_analysis` 仅在原题字段为空时写回，原题已有则保留；
- 前端详情页继续渲染 `question.answer_md` / `explanation_md`；
- 补测试：原题无答案 → 分析后填充；原题有答案 → 不覆盖。

这条和 #5/#6 的 review 阻塞是同一件事，修完一起合。

## 4. 并发与下游

- `TASK_MAX_CONCURRENCY` 默认 **6**，配置可调；实测 3 段同瞬间并发无 429，但生产仍需监控 RPM/TPM。
- BE-008 种子脚本：**直接插库** 3 条 `generated_questions`（带 `target_index`/`difficulty`），不跑真模型。
- BE-013 统计：生题成功率按**段**统计，不按“次”；PRD 5.5 埋点表补一行。

## 5. 图片提取实测（§7）回复

1. 多题提取方向通过，接受；但 1 张图不能当验收，BE-017 仍需 8–10 张不同类型真实题图。
2. **必须先转正再发**：前端裁剪步骤加“左转/右转”，后端也做一次方向判定/EXIF 处理；写进 05。
3. **压缩口径**：上传/落库仍 ≤2000px/5MB；**送 LLM 提取前压到长边 1200**（实测 token/延迟明显下降，质量不掉）。
4. **识图超时**：P0 用 **120s 同步、不自动重试**；超时返回 `AI_TIMEOUT`，用户可重传/改文本；异步识图为 P1。
5. **残缺条目**：提取并返回 `warnings` + `incomplete=true`，由用户在确认步骤决定留不留；验收口径按“完整+不完整条目都返回，用户确认后计入”记录。
6. 探针脚本可以提交到 `backend/scripts/`；**真实题图不要进仓库**，用合成图或脱敏图；脚本里图片路径走本地参数。
