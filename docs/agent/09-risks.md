## 2. 重点风险详解

### R-001 范围过大（最可能致命）

**触发信号**：

- 11.10 还没有跑通“登录 → 录入 → 生成 → 保存”。
- 11.14 没有部署地址。
- 团队在讨论独立 OCR/知识图谱/推荐算法，而不是主闭环。
- 设计稿页面超过 10 个，且都不是演示路径。

**缓解**：

1. 一切以 `01-project.md` 的 P0 为准；新需求先问“是否在 11.29 演示路径上”。
2. 11.14 前只做纵向切片；P1 从 11.15 才开始。
3. 每周日做一次范围审计：P0 是否超过 10 项？超过就砍。
4. 任何新增 P0 必须删掉一个同等工作量的 P0，或在 ADR 记录。
5. 记住：**评审看的是完整闭环和稳定性，不是功能数量**。

**负责人**：两人。**复盘**：每周日。

### R-002 AI 输出不是合法 JSON

**触发信号**：

- 模型返回 ```json 代码围栏、前后解释文字、字段名不一致。
- 生成题数量不是 3，或 `answer_md` 为空。
- 本地能跑，换个题目就失败。

**缓解**：

1. 优先用供应商的 JSON mode/structured output；没有就用严格 prompt + 示例。
2. 后端用 Pydantic `model_validate_json`；解析前去掉代码围栏、首尾空白。
3. 失败重试 1 次，把错误信息带给模型（repair prompt）；仍失败返回 `AI_INVALID_OUTPUT`。
4. 保存 `raw_response` 到 `ai_call_logs`（截断），便于排查。
5. 测试覆盖：合法 JSON、带围栏、字段缺失、数量不足、乱码。
6. **不要**把“解析失败”静默吞掉变成空列表；用户会以为生成成功。

**负责人**：人机。**验收**：20 道真实错题，结构化成功率 ≥ 95%（含重试）。

### R-003 生成题不可作答/依赖图片/与原题重复

**触发信号**：

- 生成题出现“如图所示”“根据上图”“同上”。
- 3 道题只是换了数字，题干结构完全一样。
- 题目需要画图/表格，但系统不显示图。
- 生成题和原题文本高度相似。

**缓解**：

1. Prompt 明确：**纯文本可独立作答；禁止“如图/图中/下图”；不得依赖原题图片；不得使用“同上”**。
2. 校验：检测“如图/图中/下图/上图/下表”等词；命中则判无效。
3. 去重：归一化（去空格/标点/数字）后与原题比较；相似度 ≥ 0.9 判无效。
4. 难度/题型/知识点必须与解析结果一致；不一致判无效。
5. 原题含图时，识图阶段写入图形/表格描述；生成题只做纯文本变体，不要求模型生成图片；描述不足时标记“含图题，生成题可能不完整”。
6. 人工抽检 20 组，记录“可作答率”。

**负责人**：人机。**验收**：抽检可作答率 ≥ 80%。

### R-004 生成题答案错误

**触发信号**：

- 人工抽检发现答案/解析不一致。
- 同一题两次生成答案不同。
- 复杂计算/证明题错误率明显高。

**缓解**：

1. Prompt 要求“先解题再输出答案”，但输出只保留结果和解析。
2. 可选二次校验：让模型独立解题，比较答案；不一致则标记/重试。默认关闭（成本/延迟），抽检时开启。
3. 前端提供“报错/答案有误”反馈；记录到 `generated_questions`/反馈表。
4. 演示选题避开超复杂证明题；用可验证的计算题/应用题。
5. 答辩时不要宣称“答案 100% 正确”；讲“结构化 + 校验 + 反馈 + 人工抽检”的质量体系。

**负责人**：人机。**验收**：抽检答案基本正确率 ≥ 80%；错误有反馈入口。

### R-005 数学公式/Markdown 渲染崩

**触发信号**：

- `$...$`、`\(...\)`、`\[...\]` 混用，KaTeX 报错。
- 长公式横向溢出；移动端无法阅读。
- AI 返回 HTML/脚本，`v-html` 直接渲染。
- Markdown 表格/列表/代码块样式错乱。

**缓解**：

1. 后端规范化 LaTeX 分隔符：统一 `$...$` / `$$...$$`；不合法则转义/降级为纯文本。
2. 前端统一 `MarkdownRenderer`：markdown-it + KaTeX + DOMPurify；业务组件禁止直接 `v-html`。
3. KaTeX 用 `throwOnError: false`，渲染失败降级显示原文，不白屏。
4. 长公式容器 `overflow-x: auto`；移动端允许横向滚动。
5. 测试用例：二次函数、分式、根号、积分、矩阵、长题干、表格、代码块。
6. 禁止 AI 输出 `<script>`/`<iframe>`；DOMPurify 白名单。

**负责人**：霹雳马桶。**验收**：10 条真实公式全部正常渲染；XSS 测试不执行脚本。

### R-006 多模态识图（DeepSeek）不准/慢/贵

**触发信号**：

- 公式、图表、手写体识别错误率高；题干缺项/乱码。
- 图片上传后 30 秒没结果；识图比文本慢很多。
- 图片 token 成本明显高于文本。
- 用户不核对识图结果，直接分析出错误结果。
- 框题框错/把多题框在一起；用户误确认导致混题。

**缓解**：

1. **不做独立 OCR**；用 DeepSeek `deepseek-flash` 多模态直读；**文本入口始终保底**。
2. 识图结果必须可编辑，原图并排对照；用户确认后再创建错题/分析。
3. 限制图片 5MB、最长边 2000px、JPEG/PNG/WebP；Pillow 校验真实格式、纠正旋转、去 EXIF。
4. 框题可能框错/把多题框在一起：必须让用户确认/切换候选，并允许移动/缩放 AI 框；从零画框 P1；失败退回整图识图或文本。
5. 识图 prompt：保留 LaTeX、图形/表格用文字描述、看不清标 `[不清]`、不要解题。
6. 演示用清晰打印/工整题图；准备 3–5 张；不要现场拍模糊照片。
7. 文案写“识图结果仅供参考，请核对后提交”；失败可重拍/换图/粘贴文本。
8. 识图模型只能用 `deepseek-flash`；`deepseek-v4-pro` 不支持图片。

**负责人**：人机（接口）/ 霹雳马桶（交互）。**决策**：P0 增强（文本必保）。

### R-007 SSE 在 nginx/鉴权/浏览器下失败

**触发信号**：

- 本地能收到事件，部署后一次性收到/收不到。
- EventSource 无法带 Authorization 或 POST。
- 代理超时断开；用户取消后后端还在生成。
- CORS 预检失败。

**缓解**：

1. 用 `fetch` + `ReadableStream`，不用 `EventSource`；支持 POST/Authorization/AbortController。
2. nginx：SSE 路径 `proxy_buffering off; proxy_read_timeout 120s;`；响应头 `X-Accel-Buffering: no`。
3. 心跳 15s；客户端断连检测；后端停止生成/记录。
4. 失败回退同步 `/generate`；前端提示“已切换为普通模式”。
5. 在 staging 上专门测 SSE，不只本地测。
6. **MVP 做阶段级 SSE**，不做 token 级；减少解析/缓冲/断线复杂度。

**负责人**：两人。**验收**：部署环境逐条收到 stage/question/done。

### R-008 SQLite/MySQL 差异导致部署失败

**触发信号**：

- 本地 SQLite 正常，MySQL 迁移报错。
- 中文乱码/emoji 报错。
- 大小写搜索行为不一致。
- JSON 字段查询报错。
- SQLite “database is locked”。

**缓解**：

1. 只用 SQLAlchemy ORM；不写方言 SQL；不用数据库 JSON 查询。
2. 时间存 UTC naive；展示 +8；不依赖数据库时区函数。
3. MySQL 用 `utf8mb4`；连接串带 `charset=utf8mb4`；需要索引的字段控制长度。
4. SQLite 开 WAL + `busy_timeout=5000` + `foreign_keys=ON`；部署 1 worker。
5. Alembic 迁移在 SQLite 和 MySQL 都跑；CI 至少跑 SQLite，部署前跑 MySQL。
6. 11.14 前在 staging 用 MySQL 跑一遍完整流程；不要等到 11.28。
7. 如果 MySQL 部署持续出问题，演示可退回 SQLite + WAL（单用户/低并发），但要提前演练。

**负责人**：人机。**验收**：同一套迁移在两种数据库通过；完整流程无差异。

### R-009 部署拖到最后

**触发信号**：

- 11.10 还没选服务器/平台。
- “等功能做完再部署”。
- 部署步骤只在某个人电脑上成功。
- 没有 `.env.example`/Dockerfile/nginx 配置。

**缓解**：

1. **11.7 前完成部署 spike**：一个 hello world + MySQL 能访问。
2. **11.14 必须有 staging 地址**，作为 M1 退出条件。
3. 部署脚本/README 从第一天写；环境变量模板化。
4. 每次合并 `main` 后部署一次，不要积压。
5. 准备回滚：保留上一个镜像/commit；数据库迁移向前兼容。
6. 演示前 11.28 冻结，只修 P0。

**负责人**：人机。**验收**：11.14 起每天有一个可访问地址。

### R-010 前后端契约漂移

**触发信号**：

- 前端按 Mock 写完，后端字段名不同。
- 后端改了 `snake_case`/分页/错误码，没通知。
- 联调时大量 422/500。
- 同一接口有两种响应格式。

**缓解**：

1. 11.7 冻结 API v0；11.8 冻结 v1（只加不改）。
2. 改接口先改 `05-architecture.md`，再改代码；PR 标注 BREAKING。
3. 后端 OpenAPI 自动生成；前端用 `openapi-typescript` 生成类型（或手写并对照）。
4. 前端 Mock 字段与契约完全一致；不用“先随便写，联调再改”。
5. 每天站会同步“今天有没有接口变更”。
6. 联调时用同一份 seed 数据/同一套错误码。

**负责人**：两人。**验收**：OpenAPI diff 无未确认变更；联调 1 天内完成。

### R-011 密钥泄露/越权/上传漏洞

**触发信号**：

- 前端代码/网络请求出现 `sk-...`。
- `.env` 被提交；日志打印 token。
- 用户 A 能通过改 ID 读用户 B 的错题。
- 上传 `.php/.html` 能被访问执行。
- CORS `*` + credentials。

**缓解**：

1. LLM key 只在后端 `.env`；前端只用 `VITE_API_BASE_URL`。
2. `.gitignore` 覆盖 `.env`；提交前 `git status`/secret scan。
3. 所有 question/generated/practice 查询带 `user_id` 条件；写测试验证越权。
4. 上传：MIME/大小/真实格式校验；UUID 文件名；存非 Web 根目录；鉴权下载。
5. CORS 白名单；错误响应不返回堆栈；日志脱敏。
6. JWT secret ≥ 32 字节；密码 bcrypt/argon2；登录限流。
7. AI 输出 sanitize，防 XSS。

**负责人**：两人。**验收**：越权测试 403；仓库无密钥；上传不可执行。

### R-012 LLM 供应商故障/额度/超时

**触发信号**：

- 文本生成 > 60s / 识图 > 90s；频繁 429/5xx。
- 额度不足/欠费；图片 token 消耗超预期。
- 演示现场网络不稳。
- 同一 prompt 结果质量波动大。

**缓解**：

1. **已定 DeepSeek `deepseek-flash`**；11.5 spike 验证 JSON、图片识图、延迟、价格、限流；`deepseek-v4-pro` 不支持图片。
2. 预充值；设置预算/用量告警；每用户限流（含识图次数）。
3. 文本超时 60s、识图 90s；重试 2 次、熔断 60s；错误码明确。
4. 演示账号准备**预生成缓存**（含识图结果）：`DEMO_FALLBACK_ENABLED=true`，失败时返回缓存并标注“演示缓存”。
5. 准备备用 key；识图故障时退回文本入口，不要阻塞演示。
6. 演示前 1 天用真实网络跑 3 次；准备录屏。

**负责人**：人机。**验收**：断网/限流时页面有提示，演示有兜底。

### R-013 前端缺 loading/empty/error

**触发信号**：

- AI 请求时只转圈，没有阶段说明。
- 列表无数据时空白；筛选无结果时以为坏了。
- 接口 500 时白屏/控制台报错。
- 重复点击生成，创建多条记录。
- 刷新页面登录态丢失。

**缓解**：

1. 每个异步动作设计四态：loading / empty / error / success；AI 额外有 partial。
2. 统一 `LoadingSkeleton`、`EmptyState`、`ErrorState` 组件；至少 5 处使用。
3. AI 阶段文案：“正在分析题目 → 正在生成 3 道题 → 正在校验”；给预计等待提示。
4. 按钮 loading + 禁用；请求幂等/防重复。
5. 401 拦截跳登录；404 页面；全局错误提示。
6. 表单草稿存 localStorage，AI 失败不丢输入。

**负责人**：霹雳马桶。**验收**：手动清单逐项通过；无白屏。

### R-014 演示数据不足/现场翻车

**触发信号**：

- 演示账号没有错题/练习记录。
- 统计页全是 0，讲不出故事。
- 现场输入长题干/拍照，耗时或失败。
- 网络/投影/浏览器不配合。

**缓解**：

1. 11.24 准备：2 个账号、10+ 错题、20+ 练习、不同学科/知识点、1 个薄弱点明显的数据。
2. 演示脚本只用预置数据；不现场输入长文本/拍照。
3. 准备 3 分钟录屏 + 关键截图；本地可播放。
4. 提前在演示机器/投影分辨率（1366×768）走一遍；检查字体/对比度。
5. 准备热点/备用网络；浏览器提前登录；关闭通知。
6. 演示前 3 次彩排，计时。

**负责人**：两人。**验收**：连续 3 次演示成功。

### R-015 两人协作/知识孤岛

**触发信号**：

- 只有一个人能部署/跑数据库。
- 另一个人看不懂对方代码。
- 任务互相等待，没有并行。
- 关键决定只在聊天里，没有文档。

**缓解**：

1. 每人都能跑起对方项目（11.7 前互相演示一次）。
2. API 契约 + Mock，减少等待。
3. 短分支 + PR + 互相 review；不要各自憋大招。
4. 部署 README 由两人一起走一遍；至少两人都有服务器权限/操作步骤。
5. 每天 15 分钟站会；每周复盘。
6. 关键决定写 ADR/文档。

**负责人**：两人。**验收**：任意一人能独立启动/部署/演示。

### R-016 文档腐化

**触发信号**：

- 文档写的接口和代码不一致。
- 任务状态长期不更新。
- agent 按旧文档生成了错误代码。
- 同一问题有多个互相矛盾的说明。

**缓解**：

1. 事实来源优先级写清楚（`docs/agent/README.md`）。
2. 改 API/结构必须同 PR 更新文档。
3. 每个里程碑更新 `00-context.md`/`03-roadmap.md`/`04-todos.md`。

**负责人**：霹雳马桶。**验收**：随机抽查 3 个接口，文档与代码一致。

### R-017 性能问题

**触发信号**：

4. 移动端至少录入/列表/练习三页可用；侧边栏折叠。

**负责人**：霹雳马桶。**验收**：三档分辨率 + 两浏览器通过。

### R-020 版权/隐私

### R-021 过度设计/技术债

## 3. 实现注意事项（按模块）

### 3.1 AI / Prompt

- 用 JSON mode；没有就用严格 schema + few-shot + repair。
- Prompt 版本化；不要线上直接改 prompt 不记录。
- 用户输入用分隔符包裹；防 prompt injection（至少不让模型执行指令）。
- 温度：分析 0.2，生成 0.7；不要用 1.0 导致跑题。
- 限制 `max_tokens`；避免无限生成/费用失控。
- 记录 token/延迟/模型/版本；否则无法优化/答辩。
- 不要把完整题目/答案写进普通日志；用 ID。
- 生成题必须“纯文本可作答”；这是最容易忽略的质量约束。
- 生成题与解析结果的知识点/题型/难度要一致；不一致就是“看起来像”的假相似。
- 3 题要“同知识点、不同情境/数字”，不要只换数字。
- 失败要可重试；不要静默返回空。

### 3.2 数学/Markdown

- 统一 LaTeX 分隔符；KaTeX `throwOnError: false`。
- DOMPurify 白名单；禁止 `script/iframe/on*`。
- 长公式横向滚动；不要让整个页面横向滚动。
- 代码块/表格样式要测；AI 可能返回 Markdown 表格。
- 移动端字号不小于 14px；公式可缩放。

### 3.3 多模态识图（不做独立 OCR）

- 用 DeepSeek `deepseek-flash` 直读图片，不接独立 OCR 服务。
- 结果必须可编辑；原图并排对照；用户确认后再分析。
- 图片压缩/旋转/格式校验；应用层 ≤5MB、最长边 2000px。
- 识图 prompt：保留 LaTeX、描述图形/表格、标记 `[不清]`、不要解题。
- 不要承诺 100% 识别；文案写“请核对”。
- 演示用清晰图片；不要现场拍模糊照片。
- 成本/延迟单独记录；必要时限制每天识图次数。
- `deepseek-v4-pro` 不支持图片，识图只能用 `deepseek-flash`。

### 3.4 SSE

- 阶段级优先；token 级是 stretch。
- `fetch` + `ReadableStream`；AbortController。
- nginx 关缓冲；心跳；断连检测。
- 失败回退同步接口。
- 不要在 SSE 生成期间持有 DB 事务。
- 错误事件要含 code/message；前端能区分超时/限流/解析失败。

### 3.5 数据库

- SQLAlchemy ORM；Alembic；不要 `create_all` 上线。
- SQLite WAL + busy_timeout；MySQL utf8mb4。
- 时间 UTC；展示 +8；统计在 Python 聚合。
- 软删除；统计过滤 `deleted_at IS NULL`。
- 列表不返回全文；索引；避免 N+1。
- 迁移向前兼容：先加字段/表，再改代码；回滚不删数据。

### 3.6 认证/安全

- JWT secret 服务端；7 天过期；不做 refresh（MVP）。
- 密码 bcrypt/argon2；登录限流。
- 所有资源查询带 user_id；测试越权。
- CORS 白名单；错误不暴露堆栈。
- 上传不可执行；UUID 文件名；鉴权下载。
- 前端 sanitize；后端不返回 HTML。
- 仓库无密钥；`.env.example` 只有占位符。

### 3.7 前端体验

- 四态：loading/empty/error/success；AI 加 partial。
- 按钮防重复；请求可取消；失败保留输入。
- 401 跳登录；404 页面；全局 toast。
- 长文本/公式/图片约束；移动端三页可用。
- 统计空数据不渲染空图表。
- 演示分辨率 1366×768 优先。
- 不要用 `v-html` 未清洗内容。
- 不要在前端存 LLM key。
- **Arco 版本兼容**：Vue 3.5 有社区报告的 Tooltip+Table、virtual-scroller+Collapse 问题；脚手架先 spike，必要时锁 Vue 3.4。
- **Arco 缺组件**：没有 Chat/MessageList/Markdown/Charts；聊天/流式面板、Markdown 渲染、图表都要自建/接第三方，不要低估工作量。
- **Tailwind/reset 冲突**：Arco 自带 normalize.css；若引入 Tailwind，先 `preflight: false` 或调整 CSS 顺序，并用真实页面验证 Button/Switch/Form。
- **主题**：CSS 变量是 RGB 通道（如 `--arcoblue-6: 22, 93, 255`），改主色要覆盖完整 1–10 色阶；暗色模式是 `body[arco-theme='dark']`，与 Tailwind `.dark` 要同步。

### 3.8 测试

- LLM 全 mock；fixture 覆盖合法/非法/超时。
- 越权测试；重复提交测试；空数据测试。
- 前端 E2E 主流程 + 失败路径。
- CI 每次 PR。
- 演示前回归清单。

### 3.9 部署

- 11.7 spike；11.14 staging；11.28 冻结。
- Docker Compose + nginx；`.env.example`；健康检查。
- SSE 路径关缓冲；上传卷持久化；MySQL 备份。
- 回滚步骤写下来；保留上一个可用 tag。
- 演示前检查网络/额度/证书/端口。

## 5. 答辩风险

| 风险 | 应对 |
|---|---|
| 被问“为什么不用 docx 里的 SpringBoot/langchain4j” | 技术栈已确认；Python/FastAPI 更适合 LLM/异步/快速交付；docx 是早期申报材料 |
| 被问“创新点是什么” | 闭环：生成 + 校验 + 练习 + 薄弱点；不是单纯 AI 出题 |
| 被问“答案错了怎么办” | 结构化校验 + 重试 + 用户反馈 + 人工抽检；不宣称 100% |
| 被问“知识图谱/模型训练呢” | MVP 用标签；训练/图谱是未来规划；不硬吹 |
| 被问“为什么不做 OCR” | 独立 OCR 对公式/图表/手写体支持有限；DeepSeek `deepseek-flash` 多模态直读图文，链路短；结果可编辑 + 文本兜底 |
| 被问“两人怎么分工” | 前端/后端主责 + 设计/部署/测试共担；PR/CI/文档 |
| 被问“数据隐私” | 密钥服务端；不训练；最小化日志；可删除 |
| 被问“和搜题产品区别” | 他们给答案，我们给同类题 + 掌握度 |
| 演示超时 | 只走主闭环；预置数据；提前彩排；有人计时 |
| 演示失败 | 录屏/截图兜底；说明“网络/额度问题，已准备录屏” |

## 7. 一句话总结

这个项目最大的风险不是“AI 不够强”，而是**范围失控 + 联调/部署拖到最后 + 演示没有兜底**。
