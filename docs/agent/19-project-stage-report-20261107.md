# 项目阶段性汇报（2026-11-07）

## 一、一句话概括

**技术栈和工程骨架已经搭好，前后端核心闭环已经跑通，真实 DeepSeek 也已验证；当前进入补周边功能、准备演示数据和部署的阶段。**

## 二、当前阶段

- 产品设计、技术选型、仓库骨架基本完成。
- 核心闭环已经能真实跑通：登录 → 录入错题 → AI 分析 → 生成 3 道相似题 → 练习。
- 图片录入也能真实跑通：上传 → 识图 → 多题条目 → 入库 → 列表显示原图。
- 尚未完成 staging 部署、演示种子数据和部分周边接口，因此还不能算“完整可演示”。

## 三、已完成内容

### 1. 技术栈与工程基础

- 前端：Vue 3 + Vite + TypeScript + Arco Design。
- 后端：Python 3.13 + FastAPI + SQLAlchemy + Alembic。
- 数据库：当前开发/测试使用 SQLite；云上部署再切 MySQL 8。
- AI：DeepSeek `deepseek-flash`，文本与图片都走服务端调用。
- 仓库结构、接口契约、Mock、环境变量、CI 已就位。

### 2. 前端

- 登录/注册、首页、错题列表、错题详情、录入、编辑、任务中心、练习、统计、个人设置页面均已完成。
- 支持选择题、填空题、解答题三种题型编辑。
- 支持图片粘贴/拖入、裁剪、多题识别、逐条确认和选择生成。
- 支持草稿、任务进度轮询、三段并发生成 UI、响应式布局。
- 已有统一的空状态、错误状态、加载状态和 Markdown/公式渲染。

### 3. 后端

- 认证、错题增删改查、标签/搜索、AI 分析、相似题生成、任务队列、练习记录。
- 图片上传、鉴权取图、图片转文本、多题结构提取。
- 支持完整三题型编辑，切换题型时会清理不适用的结构。
- 生成链路支持三段并发，每一段独立状态、独立重试。

### 4. 真实联调

- 文本链路已跑通：分析完成 → 三段生成全部完成 → 生成 3 题 → 练习记录成功。
- 图片链路已跑通：上传成功 → 识图成功 → 多题入库 → 列表返回原图路径。
- 真实 DeepSeek 已验证可用；当前临时 Key 只注入后端进程，不写前端、不提交仓库。

### 5. 测试与质量

- 后端有覆盖核心接口和任务链路的自动化测试。
- 前端有单元测试，覆盖接口归一化、错误码、草稿、图片映射、统计和设置校验。
- CI 会执行前后端检查，主分支保持通过。
- 已建立文档、ADR、接口同步和交接机制。

## 四、尚未完成

- 生成题题型一致性的用户开关（后端执行部分）。
- 服务端草稿接口。
- 统计接口。
- 用户自带 AI Key 的完整后端接口。
- 两步识图（前端已准备 loading 和超时，后端链路待实现）。
- 演示种子账号、种子错题和练习数据。
- OpenAPI 导出。
- staging 部署地址。
- 云上 MySQL 切换与兼容性验证。

## 五、当前可演示范围

**可以演示：**

- 登录/注册
- 文本错题录入、列表、详情
- 题目编辑（含完整三题型）
- AI 分析
- 三段并发生成 3 道相似题
- 任务中心与失败重试
- 练习与掌握度
- 图片上传、识图、多题入库

**暂时不可用：**

- 个人设置中的 AI Key 输入（后端接口未实现）
- 生成偏好开关（后端接口未实现）
- 统计页真实数据（后端接口未实现）
- 服务端草稿（后端接口未实现）

## 六、主要风险

1. **部署还没落地**：目前只有本地可运行环境，staging 地址尚未确定。
2. **周边接口未完成**：设置、统计、草稿、题型开关仍会影响演示完整度。
3. **演示数据未准备**：真实后端目前没有完整的演示账号和种子题目。
4. **真实 AI 的不确定性**：输出质量、延迟、额度和网络都可能影响演示，需要准备兜底。
5. **MySQL 切换风险**：当前 SQLite 开发顺畅，但云上切 MySQL 前需要再做迁移和兼容性验证。

## 七、下一步

1. 完成后端周边接口：题型开关、草稿、统计、AI Key、两步识图。
2. 准备演示账号、种子错题和练习数据。
3. 确定 staging 部署目标并完成部署。
4. 在 staging 上做一次完整走查和真实 AI 彩排。
5. 准备演示脚本、备用截图/录屏和答辩材料。

## 八、结论

**项目已经过了“只有骨架”的阶段，核心闭环真实可跑；目前处于“核心功能完成、周边能力和部署收尾”的阶段。**

距离“完整可演示”还差三件事：**周边接口、演示数据、可访问的 staging 地址**。
