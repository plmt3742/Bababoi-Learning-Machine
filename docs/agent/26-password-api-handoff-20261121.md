# 26 · 密码接口对接单（改密 + 管理员重置）

> 结论（2026-11-21 最新口径）：
> 1. **修改/重置密码**：学生端在个人设置里输入**旧密码**即可设置新密码（FE-038，已接 mock；后端 BE-029）。
> 2. **忘记密码**：不做邮箱自助重置，改为**管理员授权重置**（管理端 P1，BE-030）；学生端登录页只给说明。
> 3. `users.email` 仍只是可选展示字段，不参与密码找回；不引入 SMTP。
>
> 2026-11-28 修订：ADR-010 已 Accepted，忘记密码改为「学生线上申请 → 管理员审批 → 临时密码」；本文 §3.1「不提交表单」、§3.2「不引入 `password-reset/*`」与 §3.4 的 BE-030 口径以 `docs/adr/ADR-010-scope-roles-types-subjects-stages.md` 与 `28-admin-console.md` §5 为准。改密（BE-029）内容继续有效。

## 1. 现状

- 后端 `/auth` 只有 `register` / `login` / `me`；无改密、无重置。
- 前端注册页只收集用户名/密码，**不上送 email**；`users.email` 仅种子账号有值（且是 `example.com`），设置页只展示、不能绑定。
- 没有 SMTP、验证码表或发信服务；`Q-002` 原本就写“不做找回密码/邮箱验证”。
- 前端设置页已有「重置密码」卡（FE-038），调用 `POST /auth/change-password`；后端 404/405 时自动降级为“后端未启用”。

## 2. 修改密码（已定，前端已接）

### 2.1 接口

```http
POST /api/v1/auth/change-password
Authorization: Bearer <access_token>
Content-Type: application/json

{ "current_password": "旧密码", "new_password": "新密码" }
```

| 结果 | 响应 |
|---|---|
| 204 | 无 body |
| 400 `VALIDATION_ERROR` | 新密码少于 8 位 / 超过 72 字节 / 与旧密码相同 |
| 401 `AUTH_INVALID_CREDENTIALS` | 当前密码不正确 |
| 401 `AUTH_TOKEN_EXPIRED` | 登录失效（走全局 401） |
| 429 `AUTH_RATE_LIMITED` | 改密过于频繁 |

### 2.2 后端实现要点

- 用 `verify_password(current_password, user.password_hash)` 校验旧密码；失败返回 401 `AUTH_INVALID_CREDENTIALS`，**不要**返回“用户名不存在”之类的区分信息。
- 新密码长度按 **UTF-8 字节** 校验：`8 <= len(raw) <= 128` 且 `len(raw.encode("utf-8")) <= 72`（bcrypt 只取前 72 字节，见 `core/security.py`）。
- 新旧相同直接 400，避免“改了个寂寞”。
- 更新 `password_hash` 后**吊销旧 token**：建议随 `BE-028 token_version` 一起做（`token_version += 1`，`get_current_user` 校验版本）；否则旧 JWT 还能用满 7 天。
- 限流：按用户 5 次/分钟；不要求按 IP（已登录）。
- 日志只记 user_id / 状态码，不记 body、密码、hash。

### 2.3 前端现状（FE-038）

- 设置页「重置密码」：当前密码 + 新密码 + 确认；至少 8 位且不超过 72 字节、新旧不得相同、两次一致。
- 当前密码错误只在页内提示，不会清 token（`client.ts` 已把该端点的 401 从全局登出里排除）。
- 成功后清会话、回登录页并提示“密码已更新，请用新密码重新登录”。
- 联调时确认：204、错误码、成功后旧 token 是否失效。

## 3. 忘记密码（管理员授权，最新口径）

### 3.1 学生端

- 登录页「忘记密码？」的旧入口只展开一段说明，不提交任何表单（2026-11-28 修订：新流程为 `/forgot-password` 表单，见文首与 ADR-010）：

  > 忘记密码需要管理员授权：请联系项目管理员核验身份后重置。当前版本不提供邮箱自助重置。

- 已登录用户不需要走管理员：直接在设置页「重置密码」里输入旧密码重置。

### 3.2 管理员侧（P1，管理端尚未建）

- 当前阶段由后端/项目管理员人工处理：核验身份后，用脚本或直接改库更新 `password_hash`，并提醒用户重新登录。
- 后续管理端（ADM-002/004 之后）再加：

```http
POST /api/v1/admin/users/{id}/reset-password
Authorization: Bearer <admin_token>

{ "new_password": "临时口令" }        # 或 { "generate": true } 返回一次性口令
```

- 约束：`require_admin`；不返回 `password_hash`；写操作日志（谁重置了谁、时间）；成功后 `token_version += 1` 吊销该用户所有旧 token；临时口令必须一次性/可强制改密。
- 学生端不调用这个接口。

### 3.3 为什么不做邮箱自助重置

- 注册页当前不收集邮箱，库里没有可用邮箱；种子邮箱是假地址。
- 没有 SMTP / 发信服务，临时接入会带来授权码、限额、垃圾箱和演示稳定性问题。
- 因此不引入验证码表、SMTP 配置和 `password-reset/*` 接口；`Q-002` 保持“不做找回密码/邮箱验证”，只是补充“由管理员授权重置”。（2026-11-28 修订：ADR-010 已引入 `password-reset-requests` 线上申请接口，见文首。）

### 3.4 待办

- FE-039：登录页「忘记密码」入口 + 管理员授权说明（DONE）。
- BE-030：管理员重置能力（BLOCKED，依赖管理端 ADM-002/004；当前人工处理）。
- BE-028：token_version（改密/重置后旧 token 失效的前提）。

## 4. 仍需确认的点

1. 管理端什么时候做（ADM-002/004 目前 TODO）；在它之前，人工重置的操作人/记录方式。
2. `BE-028 token_version` 是否随 BE-029/BE-030 一起合。
3. 管理员重置时是“设置临时口令”还是“生成一次性口令”，以及是否强制下次登录改密。

## 5. 联调验收

- 重置密码（学生端）：旧密码错 401 且前端不被踢；正确 204；旧 token 401；新密码可登录；限流 429。
- 登录页：登录/注册切换时“忘记密码”说明会收起；说明文案可见，不出现邮箱入口。
- 管理员重置（后续）：非 admin 403；admin 成功；旧 token 401；操作日志可查；响应不含 password_hash。
- 日志：无密码、无 token 明文。
